# Archive diagram integration

도식의 필요 판단·구성·본문 보존·기술적 검토는 공통 정본 `~/.agents/skills/diagram/SKILL.md`를 실제로 읽고 따릅니다. 이 로컬 파일은 Jekyll 렌더·Issue 첨부·출판 계약만 소유합니다. 공통 정본이 없으면 [다른 기기 설정](../../agent-kit.md)을 안내하고 중단합니다. 비공개 원문을 이 공개 저장소에 복사하지 않습니다.

먼저 `AGENTS.md`, `docs/writing-convention.md`와 대상 본문을 읽습니다. Wiki라면 `.agents/skills/wiki/SKILL.md`, `docs/wiki-authoring.md`도 읽습니다. 질문·평가는 조회·제안이며 작성 요청일 때만 승인 범위의 문서와 도식을 수정합니다.

## 이 저장소의 렌더·출판

이 저장소의 Post·Wiki·Review 본문 이미지와 도식은 **GitHub Issue에 실제 첨부 업로드한 URL**로 표시한다.
Jekyll Markdown에서는 `![설명](https://github.com/user-attachments/assets/...)`를 사용한다.
SVG를 포함한 생성 중간 파일은 저장소 밖 임시 디렉터리에 둔다. `/assets/images/`나 raw GitHub URL로 대체하지 않는다.
업로드·Issue 연결·비인증 접근·원본 바이트 보존 절차는 `AGENTS.md`의 콘텐츠 이미지 규칙을 따른다.
Next.js JSX·Tailwind 유틸·Mermaid 런타임을 옮기거나 새 클라이언트 라이브러리를 설치하지 않는다.

- 반복 생성이 필요하면 `scripts/`의 생성기를 정본으로 삼되 출력은 저장소 밖에 둔다. 검증된 SVG 원본은 Issue 첨부로 보존하고 URL·SHA-256 대응표만 출판 제외된 문서에 기록한다. 새로운 그림을 만들다가 기존 도식 전체를 재생성하지 않는다.
- 독립 SVG는 부모 페이지의 CSS 변수나 글꼴을 자동 상속하지 않는다. 이 저장소의 기존 도식처럼 **불투명한 밝은 도판**을 쓰는 경우 색을 SVG 내부에 명시하고 라이트·다크 페이지 양쪽에서 확인한다. 테마를 상속한다고 보고하지 않는다.
- 새 그림은 기존 도식의 팔레트·선·글꼴과 맞춘다. 채움·선 굵기·공간 경계로 강조하고 색만으로 정보를 구별하지 않는다. 그림자·그라디언트·장식 아이콘을 넣지 않는다.
- 시작·끝은 타원, 단계는 사각형, 조건 분기는 마름모를 기본으로 한다. 단순 관계도에 불필요한 시작·끝 노드를 추가하지 않는다.
- 연결선은 수평·수직과 둥근 직각 엘보를 우선한다. 선을 노드보다 먼저 그리고 라벨을 가로지르지 않게 한다.
- 좌표·크기·간격은 4px 격자를 우선한다. 글자를 줄여 억지로 끼워 넣지 않는다.
- 모바일 본문에서 결론이 읽히는 폭으로 만든다. 복잡하면 여러 그림으로 나누거나 위→아래로 전개한다. 큰 `viewBox`를 폭에 맞춰 축소해 글자를 못 읽게 만들지 않는다. 사이트 UI·CSS는 별도 승인 없이 바꾸지 않는다.
- SVG에 고유 접두사의 `<title>`·`<desc>`와 `role="img"`, `aria-labelledby`를 제공한다. Markdown 대체 텍스트도 그림의 관계를 설명한다.
- 그림에 스크립트·외부 이미지·외부 폰트 의존성을 넣지 않는다. 고정 수치와 기술적 식별자에만 모노스페이스를 쓴다.

## 이 저장소의 검증

1. SVG XML 파싱, 실제 Issue 첨부 연결, 비인증 HTTP 200·SHA-256 일치, 고유 접근성 ID, 문서 링크와 출판 제외 경계를 검사한다. 업로드가 막히면 기존 본문을 유지하고 실패를 보고한다.
2. SVG에 실제 도형·연결선이 있는지 확인한다. 외부 SVG는 페이지 HTML에 `<path>`가 없는 것이 정상일 수 있으므로 이미지 파일 자체를 검사한다. `<path>` 개수만으로 기술적 의미를 검증하지 않는다.
3. 일반 Jekyll 빌드 뒤 **실제 렌더된 문서**를 열어 데스크톱·모바일, 라이트·다크에서 본다. 스크린샷으로 겹침·잘림·너무 작은 글자·화살표 방향을 확인한다.
4. 텍스트는 4.5:1, 의미 있는 윤곽·화살표는 3:1 이상인지 계산한다. 배경이 아니라 실제 도형 채움과 비교하고 투명색은 합성 후 계산한다. 장식용 채움이나 배경색 후광은 별도로 구분한다.
5. 본문·근거와 각 경계·화살표·상태를 대조한다. 린트·XML 파싱·스크린샷만으로 기술 정확성을 입증했다고 하지 않는다.
6. 요청한 파일만 검증·커밋·푸시한다. 배포를 보고할 때는 일치하는 Pages 실행과 공개 이미지·본문을 확인한다. `.agents`와 작성·검증 자료는 사이트에서 제외되어야 한다.

실제로 확인한 것과 못 확인한 것을 구분해 보고한다. 공개 저장소에는 비공개 업무 사례·개인 경로·인증정보·미리보기 스크린샷을 넣지 않는다.
